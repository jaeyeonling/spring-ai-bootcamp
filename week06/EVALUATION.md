# Week 06 — 비용 분석 및 추론 엔진 비교

## 배경

FAQ 챗봇 운영 비용이 월 $2,000에 달하며, 팀 10개 추가 시 $20,000이 예상된다.
두 가지 옵션을 분석한다:

- **옵션 A**: OpenAI 유지 + 비용 최적화 (캐싱, 모델 다운그레이드)
- **옵션 B**: Ollama 자체 호스팅 (외부 API 의존성 제거)

## 기술 검토: 추론 엔진 비교

| 엔진 | 라이선스 | GPU 필요 | Spring AI 통합 | 설정 난이도 | 최적 용도 |
|------|---------|---------|---------------|-----------|---------|
| **Ollama** | MIT | 선택적 | 전용 스타터 (`spring-ai-starter-model-ollama`) | ★☆☆ 쉬움 | 개발/소규모 팀, CPU 가능 |
| **vLLM** | Apache 2.0 | 필수 | OpenAI 호환 API → `spring-ai-starter-model-openai` + `base-url` 변경 | ★★☆ 보통 | 고처리량 운영, A100/H100 |
| **TGI** | Apache 2.0 | 필수 | OpenAI 호환 API | ★★☆ 보통 | HuggingFace 생태계, 스트리밍 |
| **SGLang** | Apache 2.0 | 필수 | OpenAI 호환 API | ★★★ 어려움 | 복잡한 LLM 프로그램, 구조화 출력 |

### 엔진별 상세 분석

#### Ollama
- **설정**: Docker 한 줄 + `ollama pull <model>`. 로컬 macOS/Linux 네이티브 설치도 가능.
- **지원 모델**: llama3.2, mistral, gemma2, phi3, qwen2.5 등 200개 이상.
- **처리량**: CPU 기준 llama3.2 7B ≈ 5~15 tok/s. T4 GPU ≈ 20~40 tok/s.
- **Spring AI 통합**: `spring-ai-starter-model-ollama` 전용 스타터. `spring.ai.model.chat=ollama`로 자동 전환.

#### vLLM
- **설정**: GPU 필수. Docker + NVIDIA Container Toolkit. HuggingFace 모델 ID 직접 지정.
- **지원 모델**: HuggingFace 전체 호환. llama, mistral, qwen, gemma 계열.
- **처리량**: A10G에서 llama3.1 8B ≈ 150~200 tok/s. PagedAttention으로 메모리 효율 최고.
- **Spring AI 통합**: `spring.ai.openai.base-url=http://vllm-host:8000/v1` 설정만으로 연결. 코드 변경 없음.

#### TGI (Text Generation Inference, HuggingFace)
- **설정**: GPU 필수. HuggingFace Hub 토큰 필요. 공식 Docker 이미지 제공.
- **지원 모델**: HuggingFace Hub 전체. 양자화(GPTQ, AWQ) 지원 우수.
- **처리량**: A10G에서 llama3.1 8B ≈ 100~150 tok/s. 스트리밍 최적화.
- **Spring AI 통합**: OpenAI 호환 엔드포인트 제공. `base-url` 변경만으로 연결.

#### SGLang
- **설정**: GPU 필수. 설치 의존성 복잡. 구조화 출력(JSON 스키마) 특화.
- **지원 모델**: llama, mistral, gemma 계열 + vision 모델.
- **처리량**: A10G에서 llama3.1 8B ≈ 200~250 tok/s. RadixAttention으로 공유 prefix 캐싱.
- **Spring AI 통합**: OpenAI 호환 API. `base-url` 변경으로 연결. Function calling 지원.

## 비용 분석

### 현재 비용 구조 역산 (월 $2,000 기준)

gpt-4o-mini 단가:
- 입력: $0.15 / 1M tokens
- 출력: $0.60 / 1M tokens

FAQ 챗봇 평균 요청 가정:
- 입력: 시스템 프롬프트(200) + 검색 문서(800) + 질문(100) = **1,100 tokens**
- 출력: 답변 **200 tokens**

요청당 비용:
```
(1,100 × $0.15 + 200 × $0.60) / 1,000,000 = $0.000285/요청
```

월간 요청 수: `$2,000 / $0.000285 ≈ 7,000,000 요청/월` (약 233,000 요청/일)

손익분기점 계산:
```

```

**현재 7M 요청/월 기준 이미 자체 호스팅이 압도적으로 유리하다.**

## 분석

### 어느 옵션이 더 나은가

**현재 볼륨(7M 요청/월)에서는 옵션 B(자체 호스팅)가 순수 API 비용 기준으로 압도적이다.**

그러나 실제 의사결정에는 숨겨진 비용이 있다:

| 비용 항목 | OpenAI | 자체 호스팅 |
|---------|--------|-----------|
| 모델 품질 (gpt-4o-mini vs llama3.2) | 높음 | 낮음~보통 |
| 응답 지연 | 800ms | 2,000~5,000ms |
| 운영 복잡도 | 없음 | GPU 인스턴스 관리, 모델 업데이트 |
| 장애 대응 | OpenAI 책임 | 내부 온콜 필요 |
| 확장성 | 즉시 무한 | GPU 스케일업 필요 |

### 권장 전략: 하이브리드

```
단순 FAQ 질문 (80%) → Ollama (llama3.2)  → $0 (자체 호스팅)
복잡한 추론 필요 (20%) → OpenAI (gpt-4o-mini) → 비용의 20% = $400/월
```

Week 05에서 구축한 `MetricsService`의 `rag.llm.token.cost`로 실시간 비용을 추적하고,
복잡도 판단 로직으로 라우팅하면 **총 비용 $380(인프라) + $400(OpenAI) = $780/월**로 줄일 수 있다.

### 결론

| 시나리오 | 권장 |
|---------|------|
| 프로토타입/MVP | OpenAI API (설정 없음) |
| 볼륨 > 1.3M 요청/월 | 자체 호스팅 T4 |
| 볼륨 > 2.5M 요청/월 | 자체 호스팅 A10G |
| 데이터 컴플라이언스 이슈 | 무조건 자체 호스팅 |
| 최고 품질 필요 | OpenAI GPT-4o 유지 |

**Week 06의 핵심**: `ModelRoutingService`는 두 공급자 모두 동일 코드로 지원한다.
비즈니스 판단에 따라 프로파일만 바꾸면 된다 — 코드 변경 없음.
