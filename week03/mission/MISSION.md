# Week 03 미션: "문서가 1,000페이지로 늘었습니다"

## 상황

2주 만에 만든 FAQ 챗봇이 큰 인기를 끌고 있습니다.
너무 큰 인기. 다른 팀들이 문서를 던져넣기 시작했습니다:

- 제품 매뉴얼 (200페이지)
- 내부 정책 (150페이지)
- 엔지니어링 런북 (300페이지)
- 법무 컴플라이언스 문서 (350페이지)

합계: **약 1,000페이지**. 인메모리 `ArrayList<EmbeddedChunk>`가 한계에 달했습니다.

월요일 아침 두 가지 문제가 터집니다:

> **문제 1:** 검색에 4초 이상 소요됩니다. 무차별 코사인 유사도 루프가
> 모든 청크를 스캔합니다. 사용자들이 지연 시간에 불만을 토로하고 있습니다.
>
> **문제 2:** 주말에 핫픽스를 배포했습니다. 서버가 재시작되었습니다.
> 모든 임베딩이 사라졌습니다. 모든 것을 다시 임베딩하는 데 45분과 API 비용 12달러가
> 들었습니다. 매니저가 화가 났습니다.

기술 리더가 찾아옵니다:

> "제대로 된 벡터 데이터베이스를 써요. Qdrant가 좋다고 하더군요. 또한 직접
> ETL을 작성하는 것도 그만하세요 — Spring AI에 파이프라인이 있습니다. 금요일까지요."

## 요구사항

### API 명세

```
POST /api/ingest
Content-Type: multipart/form-data

Body:
  file: <업로드된 PDF/텍스트 문서>

응답:
{
  "filename": "product-manual.pdf",
  "chunks": 47,
  "message": "성공적으로 인제스트되었습니다"
}
```

```
POST /api/query
Content-Type: application/json

요청:
{
  "question": "전자제품의 보증 기간은 어떻게 되나요?"
}

응답:
{
  "answer": "전자제품의 보증 기간은 구매 후 24개월부터...",
  "sources": [
    "product-manual.pdf — chunk 12",
    "product-manual.pdf — chunk 13"
  ],
  "tokenUsage": {
    "promptTokens": 891,
    "completionTokens": 124,
    "totalTokens": 1015
  }
}
```

### 제약사항

- **Qdrant**를 벡터 데이터베이스로 사용 (Docker로 실행)
- Qdrant에 직접 HTTP 호출 없이 **Spring AI의 VectorStore** 인터페이스 사용
- 인제스트에는 **Spring AI의 ETL 파이프라인** (Reader -> Transformer -> Writer) 사용
- 쿼리 경로에는 VectorStore + 시스템 프롬프트 패턴 사용
- 하나의 명령어로 Qdrant와 앱을 시작할 수 있는 `docker-compose.yml` 제공
- README에 **성능 비교 표** 포함 (아래 참고)
- 쿼리 응답에 토큰 사용량 포함

### 성능 비교

### 완료 기준

`src/test/` 디렉터리의 테스트가 인수 기준을 정의합니다:
- `POST /api/ingest`가 파일을 받아 Qdrant에 청크를 저장한다
- `POST /api/query`가 소스 정보와 함께 관련 답변을 반환한다
- **서버 재시작 후에도 데이터가 유지된다** (앱 재시작 후 쿼리 — 여전히 작동)
- 1,000 청크에서 검색이 200ms 이내에 반환된다

### 선택사항: 하이브리드 검색

Qdrant는 벡터 검색과 키워드 필터링을 모두 지원합니다.
일찍 끝나면 메타데이터 필터(예: 문서 이름으로 필터링)를 추가해보세요.
