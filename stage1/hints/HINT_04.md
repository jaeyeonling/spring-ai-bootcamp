# 힌트 04: 품질 판단 불가 — 답변이 맞는지 어떻게 아는가

API가 동작합니다. 질문을 보내면 답변이 옵니다.

그런데 이 답변이 맞는지 어떻게 확인하나요?

```json
{
  "question": "마켓플레이스 상품도 14일 반품 가능한가요?",
  "answer": "네, 모든 상품은 14일 이내에 반품하실 수 있습니다."
}
```

이 답변은 **틀렸습니다.**
마켓플레이스 상품은 셀러별 정책을 따릅니다. FAQ와 정책 문서에 명시되어 있습니다.

그런데 API 응답만 보면 그럴듯합니다.

## 수동 검토의 한계

테스트 질문이 100개입니다. 하나씩 눈으로 확인하면:
- 시간이 너무 오래 걸림
- 검토자마다 기준이 다름
- 변경할 때마다 100개를 다시 확인해야 함

## 자동 평가의 기본

`data/test_questions.json`에 expected_answer가 있습니다:

```json
{
  "id": "Q023",
  "question_ko": "마켓플레이스 상품도 14일 안에 반품할 수 있나요?",
  "expected_answer": "Marketplace items follow the individual seller's return policy...",
  "tier": "medium"
}
```

가장 단순한 평가: LLM에게 채점을 맡깁니다.

```java
String evaluationPrompt = """
    질문: %s

    기대 답변: %s

    실제 답변: %s

    실제 답변이 기대 답변과 사실적으로 일치하는지 평가하세요.
    JSON으로 응답하세요: {"score": 0 또는 1, "reason": "..."}
    """.formatted(question, expectedAnswer, actualAnswer);
```

## 지금 당장 측정해보세요

100개 질문을 전부 돌리고 전체 정확도를 측정해보세요.
아마 예상보다 낮을 것입니다.

**이 수치가 Stage 2의 출발점입니다.**
M2, M3, M6를 진행하면서 이 수치가 올라가는 것을 확인하는 것이 커리큘럼의 핵심입니다.

## 이 문제가 Stage 2로 이어지는 방식

이 벽이 **M3 (관측성 & 평가)** 의 존재 이유입니다.

M3에서는 단순 정확도 측정을 넘어서:
- 실패 원인 자동 분류 (검색 실패 vs 생성 실패)
- 환각 탐지 (검색 문서에 없는 내용을 답변했는가)
- A/B 비교 (프롬프트 A가 B보다 나은가)
- 프로덕션 모니터링 (배포 후 품질 변화 감지)
