# Week 07 미션: "문서 검색이 아닌 API 호출이 필요합니다"

## 상황

챗봇은 이제 FAQ 질문을 잘 처리합니다. 하지만 고객들이 이런 것을 묻습니다:

> "주문 #12345의 배송 상태가 어떻게 되나요?"
> "지난 달 매출이 얼마였나요?"
> "환불 정책이 어떻게 되나요?"

첫 번째 두 질문은 문서 검색으로 답할 수 없습니다 — 주문 시스템과 분석 데이터베이스에
**실시간 API 호출**이 필요합니다. 세 번째는 FAQ를 검색하는 전형적인 RAG 질문입니다.

제품 매니저가 찾아옵니다:

> "고객들은 답변이 문서에서 오는지 API에서 오는지 신경 쓰지 않아요.
> 그냥 질문을 합니다. 챗봇이 자동으로 무엇을 해야 할지 파악하게 만들어주세요.
> 그리고 신뢰성 있게 — 툴 호출이 실패하거나 엉뚱한 결과를 반환하면,
> 에러를 보여주는 대신 다시 시도해야 합니다."

## 요구사항

### 1. @Tool로 3개 이상의 툴 등록

`@Tool`로 어노테이션된 메서드를 가진 Spring 빈을 만드세요:

- **`getOrderStatus(String orderId)`** — 주문 상태 반환 (모의 데이터도 됨)
- **`getMonthlyRevenue(int year, int month)`** — 매출 수치 반환 (모의 데이터)
- **`searchFaq(String query)`** — 기존 RAG 파이프라인을 툴로 래핑

LLM이 사용자의 질문을 기반으로 어떤 툴을 호출할지 결정해야 합니다.
수동 라우팅 로직 없이 — 모델이 툴 설명에서 스스로 파악합니다.

### 2. Reflection 패턴 구현

LLM이 툴을 호출하고 결과를 받은 후, 결과를 검증하도록 하세요:

1. **생성**: 툴을 호출하고 결과를 얻음
2. **검증**: LLM에게 "이 결과가 실제로 사용자 질문에 답하나요?"라고 물어봄
3. **재시도**: 아니라면 다른 방식 시도 (다른 툴, 다른 파라미터)

이것을 **reflection 패턴**이라고 합니다. 사람이 자신의 작업을 재확인하는 것과 같습니다.

설정 가능한 최대 재시도 횟수를 가진 `ReflectionService`로 구현하세요.

### 3. 혼합 질문으로 테스트

다음 질문들을 보내고 올바른 툴이 호출되는지 확인하는 테스트를 만드세요:

| 질문 | 예상 툴 |
|----------|--------------|
| "주문 #ORD-2024-001의 배송 상태는요?" | `getOrderStatus` |
| "2024년 1월 매출은 얼마인가요?" | `getMonthlyRevenue` |
| "환불 정책이 어떻게 되나요?" | `searchFaq` |
| "30일 후에 반품할 수 있나요?" | `searchFaq` |
| "주문 #ORD-2024-002 상세 정보 보여주세요" | `getOrderStatus` |

### 완료 기준

- 3개 이상의 툴이 등록되고 LLM이 호출 가능하다
- LLM이 올바른 툴로 질문을 자동 라우팅한다 (수동 if/else 없음)
- Reflection 패턴이 시뮬레이션된 오류를 최소 한 번 잡고 재시도한다
- 테스트가 최소 5개의 혼합 질문에 대해 툴 라우팅을 검증한다
- 챗봇이 단일 대화에서 세 가지 질문 유형 모두를 처리한다
