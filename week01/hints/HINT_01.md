## 문제

모든 LLM 호출에는 **토큰 제한**과 **토큰 비용**이 있습니다.

| 모델 | 컨텍스트 창 | 입력 비용 | 출력 비용 |
|-------|---------------|------------|-------------|
| gpt-4o-mini | 128K 토큰 | $0.15/1M | $0.60/1M |
| gpt-4o | 128K 토큰 | $2.50/1M | $10.00/1M |

현재 FAQ는 작습니다 (약 2,000 토큰). 하지만 다음과 같은 상황이 되면 어떨까요?
- FAQ가 100페이지로 늘어난다면? (100K+ 토큰)
- 하루 1,000건의 요청이 들어온다면? ($$$)
- 제품 매뉴얼, 정책 문서 등이 추가된다면?

## 핵심 통찰

매번 **전체** FAQ를 보낼 필요가 없습니다.
누군가 "환불은 어떻게 받나요?"라고 묻는다면, **환불 섹션**만 있으면 됩니다.

문제는: **올바른 섹션을 자동으로 어떻게 찾느냐**입니다.

키워드 매칭(`String.contains()`)은 동작하지 않습니다:
- "어떻게 돈을 돌려받나요?"에는 "환불"이라는 단어가 없습니다
- "주문 취소"는 환불과 관련 있지만 공통 키워드가 없습니다

**키워드**가 아닌 **의미**로 매칭하는 방법이 필요합니다.

## Spring AI 참고

`EmbeddingModel`이 무엇을 하는지 확인해보세요:
```java
// 텍스트를 의미를 담은 벡터(숫자의 목록)로 변환합니다
EmbeddingModel embeddingModel; // Spring AI가 자동 설정
float[] vector = embeddingModel.embed("환불은 어떻게 받나요?");
// vector = [0.023, -0.041, 0.078, ...] — OpenAI의 경우 1536차원
```

의미가 유사한 두 텍스트는 공통 단어가 없어도 유사한 벡터를 가집니다.
