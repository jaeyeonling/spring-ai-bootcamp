# Spring AI Bootcamp

## "고객지원 챗봇 만들어주세요."

CTO의 슬랙 메시지가 도착합니다.
데이터 서버에 FAQ, 정책 문서, 상담 로그가 올라왔고, API 키가 공유됐습니다.

어떤 구조로, 어떤 기술로 만들라는 말은 없습니다.
Spring Boot와 LLM API가 있으니까, 알아서 해보세요.

2주 뒤에 당신 손에 남는 건 **동작하는 챗봇 하나와, 그걸 만들면서 부딪힌 벽 목록**입니다.

---

## 왜 벽부터인가

대부분의 AI 교육은 이렇게 시작합니다:

> "벡터 DB란 임베딩을 저장하고 유사도 검색을 수행하는..."

맞는 말입니다. 근데 이걸 왜 써야 하는지는 모릅니다.

이 부트캠프는 순서가 반대입니다.

서버를 재시작했더니 데이터가 날아갑니다.
"아, 이걸 어딘가에 저장해야 하는구나."

그때 벡터 DB를 배우면, 외우는 게 아니라 **해결하는** 겁니다.

2주 동안 이런 벽을 여러 개 만납니다.
벽의 이름을 아는 것, 벽이 왜 생기는지 아는 것 --
그게 이 2주의 목표입니다.

---

## 2주 동안 일어나는 일

3개 레이어의 실제 데이터가 있습니다.

```
FAQ 12개  /  정책 문서 (현행 + 구버전)  /  고객 상담 로그 3,000건
```

이것만으로 `POST /api/chat`을 만듭니다.
처음엔 데이터를 통째로 넣어봅니다. 안 됩니다.
그러면 관련 있는 것만 찾아서 넣어봅니다. 됩니다. 근데 이상합니다.

테스트 질문 100개를 돌리면 정확도가 나옵니다.
Easy는 그럭저럭. Medium부터 급락합니다.

구버전 정책이 답변에 섞이고,
상담 로그의 구어체를 이해 못하고,
서버를 껐다 키면 처음부터 다시 해야 합니다.

이게 전부 **의도된 경험**입니다.

---

## 벽을 만난다는 것

2주가 끝나면 챗봇은 돌아갑니다. 하지만 완벽하진 않습니다.

어떤 사람은 "서버 재시작하면 데이터가 날아간다"는 벽을 만나고,
어떤 사람은 "답변이 맞는지 틀린지 확인할 방법이 없다"는 벽을 만납니다.
같은 코드를 짜도 **사람마다 부딪히는 벽이 다릅니다.**

이 과정의 마지막에는 자신이 부딪힌 벽을 정리합니다.
가장 많이 실패한 질문 유형, 왜 실패했는지, 지금 방식의 한계가 뭔지 --
정확도를 수치로 기록하고, 자기 구현의 문제를 스스로 진단합니다.

이걸 할 수 있다는 건,
AI 서비스가 왜 어려운지를 **설명이 아니라 경험으로 아는 상태**가 됐다는 뜻입니다.

---

## 이런 분을 위해 만들었습니다

- Spring Boot로 API를 만들어본 백엔드 개발자
- AI/ML 사전 지식은 필요 없습니다
- "LLM API 호출은 해봤는데, 서비스로 만드는 건 다르더라"를 느낀 분
- 도구부터 배우기보다, 왜 필요한지 먼저 이해하고 싶은 분

## 필요한 것

| 항목 | 비고 |
|------|------|
| Java 17+ | `java -version`으로 확인 |
| OpenAI API 키 | 2주 전체 $1-5 이내 |

---

## 끝나면 뭐가 남나요

동작하는 챗봇과, 내가 만든 것의 한계를 정리한 기록.

기술 이름은 몰라도 됩니다.
"검색이 부정확하다", "비용이 예상보다 높다", "답변 형식이 매번 다르다" --
이 문제들을 **직접 겪어서** 설명할 수 있게 됩니다.

그게 다음 단계를 배울 준비가 된 상태입니다.

---

## 그 다음은요?

2주 동안 만난 벽에는 해결하지 못한 문제들이 남아있습니다.

이 벽들을 하나씩 부수는 모듈형 심화 과정을 준비하고 있습니다.
벡터 DB, 검색 품질, 관측성, Tool Use, 비용 최적화, 멀티 에이전트, 스트리밍 등 --
자기가 겪은 벽에 해당하는 모듈만 골라서 진행하는 구조입니다.

**심화 과정은 이 2주 과정에 포함되어 있지 않습니다.**
추후 공개 예정입니다.
