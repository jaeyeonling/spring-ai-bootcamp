# Step 2: 현재 커리큘럼 회고

## 전체 요약

10주 커리큘럼의 **철학과 구조는 유효**하지만, **데이터가 너무 단순해서 핵심 학습 경험이 무력화**됨.
고급 전략(ReRanker, QueryTransform)이 Baseline보다 오히려 나빠지는 현상이 대표적.

- FAQ 24개 Q&A → 17개 청크 → **Baseline 82-96%** → 벽이 안 생김

- **측정 → 가설 → 개선 사이클**로 전환 필요

### 철학 (전면 유지)

- "벽에 부딪힘 → 필요성 체감 → 학습" 사이클
- 테스트 통과 = 미션 완료
- 힌트 카드 3단계 시스템
- 하나의 도메인이 진화하는 연속 구조

### 구조 변경 방향 (Step 3에서 상세화)

**기존**: 10주 고정 순차 진행
**변경**: 2단계 구조

- **Stage 1 (2주)**: LLM API 호출로 응답하는 환경을 직접 만들기 — 방대한 데이터로 벽을 체감
- **Stage 2 (모듈)**: Stage 1에서 느낀 불편함을 선택적으로 개선 — 각 모듈이 독립적

이 구조가 해결하는 기존 문제들:
- 10주 완주율 문제 → Stage 1(2주)만으로도 가치 있는 경험
- 도메인 파편화 (#14) → 전체가 하나의 FAQ 챗봇 도메인
- 수치 하드코딩 (#12) → Stage 1에서 직접 측정한 결과가 Stage 2의 동기
- 벽이 안 생김 (#5, #6) → 데이터 규모/복잡도로 벽을 보장
