# Step 1: 커리큘럼의 의미 정리

## 존재 이유

"LLM API 연결은 하는데, 그 다음을 모르는" 개발자가 한 사이클을 경험하게 하는 것.

- LLM을 서비스에 붙이는 사람은 많지만, 단순 API 연결 이후 개선을 못하는 경우가 대부분
- LLM 생태계의 개념들(RAG, 벡터DB, 에이전트 등)이 너무 많고 어려워 학습 진입장벽이 높음
- 완벽하지 않더라도 한 사이클을 전부 돌려보는 경험이 가장 효과적인 학습

## 대상 (페르소나)

Spring을 사용해 본 개발자로, 다음 중 하나에 해당:

1. **서비스에 LLM을 붙이려고 하는 개발자** — 시작점을 모르거나 API 연결 이후가 막막한 상태
2. **이미 주먹구구로 LLM 서비스를 운영 중인 개발자** — 돌아는 가는데 개선 방법을 모르는 상태
3. **LLM 발전에 뒤쳐지지 않으려는 개발자** — 사람들이 말하는 것들이 뭔지 직접 경험하고 싶은 상태

### 사전 조건

- Spring Boot로 REST API를 만들어 본 경험 (필수)
- AI/ML 사전 지식 불필요 (커리큘럼에서 다룸)

## 완주 후 도달 상태

> **"LLM 서비스를 만들고, 개선하고, 왜 그렇게 해야 하는지 설명할 수 있다"**

세 가지 능력의 결합:
- **만들기**: LLM 기반 서비스를 처음부터 프로덕션까지 한 사이클 구축할 수 있다
- **개선하기**: 문제가 생겼을 때, 뭘 고쳐야 하는지 안다
- **설명하기**: RAG, 벡터DB, 에이전트 등이 뭔지 직접 만들어봤고, 언제 필요한지 안다

## 기존 10주에서 유지할 것 / 버릴 것

### 유지

- **"벽에 부딪힘 → 필요성 체감 → 학습" 철학** — 커리큘럼의 핵심 차별점
- **하나의 도메인이 점진적으로 진화하는 구조** — 파편화된 예제가 아닌 연속된 경험
- **테스트로 완료를 검증하는 방식** — 명확한 완료 기준
- **힌트 카드 시스템** (3단계) — 자기주도 학습 지원
- **Spring AI 기반 기술 스택** — 대상 페르소나와 일치
