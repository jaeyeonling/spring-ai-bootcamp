# 힌트 01: 언제 멀티 에이전트가 필요한가

멀티 에이전트를 쓰기 전에 단일 에이전트로 충분한지 먼저 확인하세요.

## 단일 에이전트 + Tool로 충분한 경우

```
질문: "반품 기간이 얼마나 되나요?"
→ 단일 RAG 호출로 해결. 멀티 에이전트 불필요.

질문: "제 주문 20240815-042 반품하려면 어떻게 해요?"
→ getOrderStatus(Tool) + 반품 정책(RAG) 조합으로 해결.
→ Tool Use(M4)만으로 충분. 멀티 에이전트 불필요.
```

## 멀티 에이전트가 진짜 필요한 경우

```
질문: "VIP 회원인데 마켓플레이스에서 산 냉장 식품 반품할 수 있나요?"

필요한 정보:
- FAQ: 마켓플레이스 정책 (Layer 1)
- 정책 v3: 냉장 식품 규정 (Layer 2 current)
- 멤버십: VIP 예외 규정 (Layer 2 internal)
- 상담 로그: 유사 선례 (Layer 3)

단일 RAG 호출 결과: 4개 소스를 종합하지 못하고 하나만 반환함.
→ 소스별 전문 에이전트가 각각 검색 후 Orchestrator가 종합해야 함.
```

## 체크리스트

멀티 에이전트 필요 여부:

```
[ ] 여러 데이터 소스를 동시에 참조해야 하는가?
[ ] 각 소스가 다른 전처리/필터 전략이 필요한가?
[ ] 소스 간 모순을 감지하고 해결해야 하는가?
[ ] 병렬 처리로 속도 이점이 있는가?

→ 2개 이상 해당하면 멀티 에이전트 고려
→ 1개 이하면 단일 에이전트 + Tool로 먼저 시도
```

## 멀티 에이전트의 비용

- LLM 호출 횟수 = 에이전트 수 × 2 (검색 + 생성) + Orchestrator 1
- 3개 Worker + 1 Orchestrator = 최소 7회 LLM 호출
- 단일 RAG 대비 5-7배 비용, 2-3배 지연시간

이 비용이 정확도 향상으로 정당화되는지 측정하세요.
