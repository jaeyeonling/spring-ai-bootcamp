# Week 09 미션: "IDE에서 직접 사용하고 싶습니다"

## 상황

AI 기반 서비스가 작동합니다. FAQ 챗봇이 질문에 답합니다. 멀티 에이전트 PR 리뷰어가
상세한 보고서를 만들어냅니다. 하지만 문제가 있습니다:

> 모든 툴이 별도의 웹 앱입니다. 사용자들이 IDE를 벗어나 브라우저를 열고,
> 코드를 붙여넣고, 결과를 복사해야 합니다.

팀 리더가 말합니다:

> "Claude Desktop에서 바로 사용할 수 있게 할 수 있나요? 아니면 Cursor에서? 아니면 어떤 AI 클라이언트에서든?
> 또 다른 웹 앱은 필요 없어요. 편집기에서 바로 사용하고 싶어요."

**MCP** — Model Context Protocol — 가 등장합니다. MCP는 AI 어시스턴트가 단일 프로토콜을 통해
외부 툴에 연결할 수 있게 하는 개방형 표준입니다. REST API를 만드는 대신 **MCP 서버**를 만듭니다.
MCP 호환 클라이언트(Claude Desktop, Cursor 등)가 여러분의 툴을 자동으로 발견하고 사용할 수 있습니다.

이렇게 생각하세요:

| 방식 | 여러분이 만드는 것 | 사용자가 하는 것 |
|----------|-----------|-----------|
| REST API | 엔드포인트 + 문서 + 클라이언트 코드 | 문서 읽기, HTTP 호출 작성 |
| MCP 서버 | 어노테이션이 달린 메서드 | 한 번 연결하면 툴이 자동으로 나타남 |

## 요구사항

### 목표

기존 기능을 MCP 호환 클라이언트에 노출하는 MCP 서버를 만드세요.
**Spring AI MCP Boot Starter**를 사용해 모든 것을 자동 설정합니다.

### 3가지 MCP 프리미티브

MCP는 정확히 세 가지 프리미티브를 정의합니다. **세 가지 모두** 사용해야 합니다:

| 프리미티브 | 비유 | 어노테이션 | 목적 |
|-----------|---------|------------|---------|
| **Tools** | POST 엔드포인트 | `@Tool` | AI가 호출할 수 있는 액션 (FAQ 검색, 주문 조회) |
| **Resources** | GET 엔드포인트 | `@Tool`로 구현 | AI가 읽을 수 있는 데이터 (FAQ 문서 목록, 설정) |
| **Prompts** | 템플릿 | `@Tool`로 구현 | AI가 사용할 수 있는 재사용 가능한 프롬프트 템플릿 |

### 노출할 서비스

1. **FaqMcpService** — MCP를 통해 FAQ 기능 노출:
   - `@Tool` — 쿼리로 FAQ 검색
   - `@Tool` — 모든 FAQ 문서/카테고리 목록 반환 (Resource 역할)
   - `@Tool` — 고객지원 프롬프트 템플릿 반환 (Prompt 역할)

2. **OrderMcpService** — MCP를 통해 주문 기능 노출:
   - `@Tool` — ID로 주문 조회
   - `@Tool` — 주문 상태 확인

### 테스트

다음 중 하나를 사용해 MCP 서버 테스트:
- **MCP Inspector** — MCP 서버를 검사하고 테스트하는 CLI 툴
- **Claude Desktop** — 서버를 연결하고 대화에서 사용
- **Cursor** — MCP 툴 공급자로 설정

### 완료 기준

- MCP 서버가 시작되고 툴을 등록한다
- 최소 3개의 `@Tool` 메서드가 구현된다 (검색, 카테고리 목록, 주문 조회 등)
- MCP 클라이언트(inspector, Claude Desktop, Cursor)가 여러분의 툴을 발견하고 호출할 수 있다
- MCP를 통해 FAQ 검색과 주문 조회가 엔드투엔드로 작동한다
